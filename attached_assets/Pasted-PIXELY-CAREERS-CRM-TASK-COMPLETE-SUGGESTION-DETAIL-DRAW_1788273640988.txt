==================================================
CURRENT UX PROBLEM
==================================================

The Suggestion drawer currently feels like raw database information.

Current problems include:

1. The actual Suggestion text does not receive enough visual importance.

2. Metadata such as:

Added By
Reviewed By
Related Order

takes too much space compared with the Suggestion itself.

3. "Reviewed By" is now confusing because Suggestions no longer have an Under Review workflow.

4. Admin Notes behave like one editable field.

Existing notes should NOT remain inside an editable textarea.

5. Rejection Reason appears as a disconnected field near the bottom instead of being part of a clear final Management Decision section.

6. There is no strong hierarchy between:

Suggestion
Evidence
Decision
Admin Notes
History

7. History should use the same clean human-readable timeline as Order Activity and Complaint Case History.

==================================================
CORE DESIGN PRINCIPLE
==================================================

The Suggestion drawer should answer these questions immediately:

1. WHAT WAS SUGGESTED?
2. WHICH CLIENT / ORDER DOES IT RELATE TO?
3. WHICH DESIGNER WAS ASSOCIATED WITH IT?
4. WHO RECORDED THE SUGGESTION?
5. IS THERE ANY EVIDENCE?
6. WHAT DID MANAGEMENT DECIDE?
7. WHY WAS IT IMPLEMENTED OR REJECTED?
8. WHAT INTERNAL NOTES EXIST?
9. WHO DID WHAT AND WHEN?

The page should feel like a clean improvement record, not a database form.

==================================================
FINAL PRODUCT STANDARD
==================================================

A Suggestion is NOT a complicated workflow.

The employee records what the client suggested.

Management then makes ONE decision:

IMPLEMENT IT

or

REJECT IT.

The drawer should make that story obvious:

WHAT DID THE CLIENT SUGGEST?

WHO/WHICH ORDER IS IT ABOUT?

WHAT EVIDENCE EXISTS?

WHAT DID MANAGEMENT DECIDE?

WHY?

WHO MADE THE DECISION?

WHEN?

WHAT INTERNAL NOTES EXIST?

WHAT HAPPENED OVER TIME?

Make the backend structured and auditable.

Make the frontend simple, clean and immediately understandable.
