==================================================
CORE BUSINESS RULE
==================================================

A CLIENT REVIEW IS NOT A WORKFLOW.

We are NOT tracking a review through stages.

We are simply RECORDING feedback already received from a client.

Therefore REMOVE from the Review UI:

- Review Progress
- Progress bar
- Feedback Requested
- Feedback Received
- Public Review Added
- Completed
- Progress-stage explanations
- Progress status controls
- Progress-related history/log entries
- Any review workflow that makes the Review look like a task-management system

The Review is simply a CLIENT FEEDBACK RECORD.

==================================================
DATABASE SAFETY
==================================================

If an existing review_progress/status field already exists in Supabase:

DO NOT delete it destructively if that could break existing data or migrations.

It may remain internally for backward compatibility if required.

However:

- Do not show it in the UI.
- Do not require it when creating Reviews.
- Do not use it for Review metrics.
- Do not create new progress history events.
- Do not make users manage it.

If it can be safely deprecated without breaking anything, document that at the end.

==================================================
WHAT A REVIEW SHOULD RECORD
==================================================

A Review needs to answer only:

1. Which client gave the feedback?
2. Which Order does it belong to?
3. Which Designer handled the Order?
4. What rating did the client give?
5. What did the client say?
6. Where was the feedback received?
7. Is there public-review evidence?
8. Is there screenshot/evidence?
9. Does Pixely have permission to use it?
10. Which staff member recorded the Review?
11. When was it recorded?

That is all.
