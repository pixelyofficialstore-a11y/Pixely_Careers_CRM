I want to improve Admin order management permissions in my existing CRM.

Project Context:
This is Pixely_CRM for Pixely Careers. The CRM has an Orders Management page where orders are created, assigned to designers, tracked by status, and connected with payment/finance data.

Change Required:
Admin should have full control over existing orders.

Admin should be able to:
1. Change assigned designer
2. Edit package/services
3. Add services
4. Remove services
5. Increase or decrease total bill
6. Update payment/finance details accordingly
7. Delete an order completely from the CRM/database

IMPORTANT:
These permissions should be for Admin only unless the existing system already allows higher-level roles. Designers or normal team users should not be able to perform these admin-level changes unless explicitly allowed.

PART 1: ADMIN CAN CHANGE ASSIGNED DESIGNER

Required Behavior:
Admin should be able to edit the assigned designer of any order after the order has been created.

Example:
Order PX-2607-413 is assigned to Abdullah Butt.
Admin should be able to change it to Muhammad Anas.

Requirements:
1. Add an edit option or dropdown for assigned designer.
2. Admin can select another active designer/team member.
3. Save the change in the database.
4. Order table should update immediately.
5. Designer dashboard/workload should update if applicable.
6. Old designer should no longer see that order if designer-specific access exists.
7. New designer should see the order if designer-specific access exists.
8. Create a clear notification:
   Order Reassigned
   PX-2607-413 for Adnan was reassigned from Abdullah Butt to Muhammad Anas by Soban Masood.

PART 2: ADMIN CAN EDIT PACKAGE / SERVICES

Required Behavior:
Admin should be able to edit the package or services of an existing order.

Admin should be able to:
1. Change package type
2. Add extra services
3. Remove existing services
4. Edit service quantity
5. Edit service instructions
6. Update custom services
7. Save changes without breaking the order

Example:
Current package:

Admin can change it to:

Or remove:
Naukri Gulf Profile

Requirements:
1. Add an Edit Order option for Admin.
2. In Edit Order modal/page, show current selected package/services.
3. Admin should be able to modify services.
4. Service list should update in the order table and export reports.
5. The updated package/services should be reflected everywhere:
   - Orders page
   - Order details
   - Designer view
   - Export PDF
   - Notifications if relevant
   - Finance calculations if related

PART 3: ADMIN CAN ADD OR SUBTRACT TOTAL BILL

Required Behavior:
Admin should be able to manually adjust the total order bill.

Admin should be able to:
1. Increase total package amount
2. Decrease total package amount
3. Add discount
4. Remove discount
5. Update final payable amount
6. Update advance payment
7. Update remaining amount
8. Update collected amount if needed

Finance Fields To Support:
Total Package Amount
Discount Amount
Final Payable Amount
Advance Payment
Collected Amount
Remaining Amount
Payment Status
Payment Method
Payment Date
Notes / Reason for Adjustment

Finance Calculation Logic:
Final Payable Amount = Total Package Amount - Discount Amount

Collected Amount = Total amount received from client

Remaining Amount = Final Payable Amount - Collected Amount

If Remaining Amount is 0:
Payment Status can become Paid if existing logic allows.

If Collected Amount is 0:
Payment Status can remain Pending.

If Collected Amount is greater than 0 but less than Final Payable Amount:
Payment Status can be Partial.

Important:
Do not show NaN.
Do not allow negative final payable unless intentionally supported.
If admin reduces the bill below collected amount, show warning or handle overpaid balance properly.

Required UI:
In Edit Order modal/page, add finance edit fields:
Total Package Amount
Discount Amount
Final Payable Amount
Advance Payment
Collected Amount
Remaining Amount
Payment Status
Payment Method
Payment Date
Adjustment Notes

Admin should be able to save changes.

PART 4: ADMIN CAN DELETE ORDER COMPLETELY

Required Behavior:
Admin should be able to delete an order completely from the CRM.

VERY IMPORTANT:
When an order is deleted, it should be completely wiped out from everywhere.

This means:
1. Delete order record from database.
2. Delete its payment/finance records.
3. Delete its notifications linked to that order.
4. Delete its assignment records.
5. Delete its revision records if any.
6. Delete its attachments/files references if any.
7. Delete it from designer view.
8. Delete it from admin orders view.
9. Delete it from payments page.
10. Delete it from analytics calculations.
11. Delete it from export reports.
12. Delete it from search results.
13. Delete all related child records connected to that order.

After deletion:
No order ID should remain.
No finance data should remain.
No payment data should remain.
No notification linked to the order should remain.
No designer assignment should remain.
No analytics count should include it.

This must be a hard delete, not soft delete.

Do not just mark the order as deleted.
Actually remove it from the database and all related tables/collections.

Important:
Before implementing, inspect the database schema and find all relations connected to orders.

Possible related data:
orders
payments
payment_verifications
notifications
assignments
order_services
custom_services
revisions
attachments
comments
activity_logs
analytics records
designer workload records

Delete all related records safely.

Security Requirement:
Only Admin can delete orders.

No designer, support user, or disabled user should be able to delete orders.

PART 5: DELETE CONFIRMATION SAFETY

Because deletion is permanent, add a strong confirmation before deleting.

Required Delete Flow:
1. Admin clicks Delete Order.
2. Show confirmation modal:
   "This action will permanently delete this order and all related finance, payment, assignment, and notification data. This cannot be undone."

3. Ask admin to confirm.
4. Preferably require typing the order ID before delete.
   Example:
   Type PX-2607-413 to confirm deletion.

5. Delete button stays disabled until correct Order ID is typed.
6. After deletion, show success message:
   "Order PX-2607-413 has been permanently deleted."

7. Refresh order list and summary cards.

PART 6: ACTIVITY LOG OPTION

If the CRM has an activity log/audit log, keep a minimal admin activity record only if required for security.

But the deleted order itself, order ID inside order tables, payment data, and finance data should be removed completely.

If activity log is kept, it should not affect search, reports, orders, finance, payments, or analytics.

If the user requirement conflicts with existing audit logs, prioritize complete removal from operational CRM data.
