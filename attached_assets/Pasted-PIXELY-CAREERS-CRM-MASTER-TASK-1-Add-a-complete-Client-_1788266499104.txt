PIXELY CAREERS CRM
MASTER TASK:

1. Add a complete Client Reviews system.
2. Add a complete Client Suggestions system.
3. Create a unified Client Feedback page.
4. Connect Reviews, Suggestions, Complaints, Payments, Orders, Assignments and other order-related activity together.
5. Build a clean chronological Order History.
6. Make the CRM behave like ONE CONNECTED SYSTEM instead of separate isolated pages.

THIS IS AN EXISTING PRODUCTION CRM.

DO NOT rebuild the application.

DO NOT break:
- Orders
- Payments
- Complaints
- Authentication
- User roles
- Designer assignment
- Notifications
- Existing dashboards
- Cloudinary payment screenshots
- Supabase database integration
- Existing complaint security/anonymity
- Existing complaint status logic

The new implementation must be ADDITIVE and carefully integrated.

==================================================
CORE ARCHITECTURE PRINCIPLE
==================================================

THE ORDER MUST BECOME THE CENTRAL SOURCE OF CONTEXT.

Every client-related record should connect back to an Order.

Conceptually:

CLIENT
   ↓
ORDER
   ├── Created By
   ├── Assigned Designer
   ├── Package / Services
   ├── Payment
   ├── Payment Screenshot
   ├── Complaints
   ├── Complaint History
   ├── Client Review
   ├── Client Suggestions
   └── Activity History

Do NOT create separate copies of Order data inside every module.

Example:

Complaint should reference order_id.
Review should reference order_id.
Suggestion should reference order_id.
Payment already references Order and should continue doing so.

Client name, package, service, payment amounts, current designer, etc. should normally be READ from the actual Order relationships.

Do not duplicate them unnecessarily.

==================================================
REVIEW NUMBER FORMAT
==================================================

Use the same philosophy as Complaint IDs.

Format:

REV-2609-001

Meaning:

REV = Review
26 = 2026
09 = September
001 = universal Review sequence

The final number must NEVER reset each month.

Example:

REV-2609-001
REV-2609-002
REV-2610-003
REV-2610-004

If the Complaints module already has a safe database-backed sequence-generation implementation:

REUSE or extend that approach.

Do not generate IDs from visible row count.

Review Number must be unique.

==================================================
ONE REVIEW PER ORDER
==================================================

Prefer one consolidated Review record per Order.

If a Review already exists and an employee selects:

Add Review

then open:

Update Review

instead of generating duplicates.

The review may be progressively updated.

Example:

Day 1:
WhatsApp feedback received.

Later:
Facebook review received.

Later:
Video review received.

All should remain part of the SAME Order Review.
