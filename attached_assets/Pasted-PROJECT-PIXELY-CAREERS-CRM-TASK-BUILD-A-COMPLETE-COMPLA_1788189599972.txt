==================================================
BUSINESS PURPOSE
==================================================

Pixely Careers wants a formal Complaint Management System connected directly to client Orders.

Complaints are mainly filed when there is an issue concerning the Designer handling an order.

The system must allow authorized staff to raise a complaint directly from an Order.

The assigned Designer must be notified that a complaint has been filed against them.

HOWEVER:

The identity of the person who filed the complaint MUST remain anonymous to the Designer.

Admins/authorized management users must be able to see who filed the complaint.

Complaints must be reviewed before they are treated as valid performance issues.

A complaint being FILED does NOT automatically mean the Designer is guilty.

Only complaints marked VALID by an authorized Admin/Manager should eventually affect performance metrics.

MODULE 1 — DATABASE / DATA MODEL
==================================================

Create a new complaints entity/table using the same database conventions already used by the CRM.

Suggested conceptual structure:

complaints

Fields:

5. complaint_against_user_id

6. filed_by_user_id

7. category

- Slow Response

- Revision Handling Issue
- Incorrect Information / Mistake

8. description
   - Required
   - Text
   - Complaint details.

9. status

Required complaint statuses:

- New
- Under Review
- Valid
- Invalid
- Resolved

Use internal slug values if preferred, for example:

new
under_review
valid
invalid
resolved

10. admin_notes
    - Optional
    - Visible only to authorized Admin/Management.
    - Must never be exposed to Designer unless intentionally designed later.

11. resolution
    - Optional text
    - Used when resolving complaint.

12. resolved_by_user_id
