==================================================
1. COMPLAINT ID FORMAT
==================================================

Change Complaint IDs to this exact format:

CMP-2606-001

Meaning:

CMP = Complaint
26 = Year 2026
06 = Month June
001 = Universal complaint sequence

Example:

CMP-2606-001
CMP-2606-002
CMP-2606-003
CMP-2607-004
CMP-2607-005
CMP-2608-006

IMPORTANT:

The final numeric sequence is GLOBAL.

IT MUST NOT RESET EACH MONTH.
IT MUST NOT RESET EACH YEAR.

If the last complaint is:

CMP-2606-099

and the next complaint is created in July 2026, it becomes:

CMP-2607-100

The date prefix should always come from the actual complaint creation date.

Do not generate complaint numbers by simply counting currently visible records because deleted/missing records could cause duplicate IDs.

Use a safe database-backed sequential mechanism consistent with the existing database architecture.

Complaint IDs must be UNIQUE.

Existing complaints should remain accessible.

If migration of old complaint numbers is necessary, handle it safely without destroying complaint records.

==================================================

- Border radius

- Spacing
- Alignment
- Hover behavior if Orders cards have it

Definitions:

ALL COMPLAINTS
Count all complaints for the currently selected period.

VALID
Count complaints with status = Valid or complaints that progressed from Valid to a valid final resolution if the data model preserves that relationship.

INVALID
Count complaints marked Invalid.

RESOLVED
Count complaints whose final complaint status is Resolved.

REFUND
Count complaints where the complaint resolution/outcome resulted in a Refund.

IMPORTANT:
Refund should NOT necessarily replace complaint status.

Complaint status workflow and resolution outcome should remain logically separate.

For example:

Complaint Status:
Resolved

Resolution Outcome:
Refund

This allows the Refund metric to work correctly.

11. IRREVERSIBLE VALIDATION
==================================================

Changing:

New → Valid

or

New → Invalid

is a serious decision.

Before applying either change, show confirmation modal:

"You are about to mark this complaint as Valid. This action cannot be undone."

"You are about to mark this complaint as Invalid. This action cannot be undone."

- New
- Invalid

Once complaint becomes Invalid:

IT CANNOT RETURN TO:
- New
- Valid

Invalid is a terminal complaint validation state.
